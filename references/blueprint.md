# 教学蓝图

先定听众能带走的结果，再倒推页面。页面按理解顺序排，不按仓库目录或原教程章节排。

## 结果

用一句话写清演示结束时听众能做什么。架构导读的默认结果是：

> 能沿一条主链路指出源码位置，并知道每类问题先找哪一层。

不要把「读完某份长教程」当成结果。

## 页表

为每一页填写：

| 页 | 本页只回答 | 学习结果 | 证据 |
|---|---|---|---|
| 01 封面 | 这套系统到底在做什么 | 建立预期，不进入 API | 入口组件 / 教程开篇 |

只保留支撑结果的页面。机制走查选一条最能代表系统的路径（加载、一次交互、一帧渲染），不要每种 API 各做一页。

## 常用放大顺序

1. 封面：一句话机制，不是功能清单
2. 少数对象：后续细节都能挂回去
3. 分层：宿主 / 编排 / 变换 / 渲染
4. 输入边界：业务到底传什么
5. 主链路：问题停在哪一站
6. 关键变换：坐标、解码、网格或状态机
7. 一次机制走查
8. 一次交互走查
9. 一帧或运行时结构
10. 成本链：CPU / 主线程 / GPU 或等价分层
11. 排障地图 + 收束链路

有经验听众默认约 10 分钟。详细 API 留在原教程或源码里。

## 教学选择

实现细节可以简化，但必须标明这是教学选择。缺证据的必要概念停下来核源码，不要用文件夹名冒充机制。源码不可运行时，仍然可以做解释型导读，不要改成阅读练习清单。

## Agent 系统材料

若材料讲的是 Agent / AI 运行时，先教最小可运行环：单轮模型 → 一个工具 → 上下文状态 → 一个外部边界 → 错误与观测。再谈并行工具、记忆和产品 UI。
